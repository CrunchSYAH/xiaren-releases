# 图片消息实现计划

目标：PNG／JPEG 图片可以作为独立消息与文字、链接混排，复用逐条授权、持久化声明、最终同步核对和断点恢复；不迁移旧任务、不扩大权限、不执行真实私信。

## 已核实的页面行为

真实页面上传组件的文件变化处理器先检查文件并异步解析本地媒体；成功回调只把媒体加入当前会话的待发送列表。编辑器发送处理器才读取该列表，逐个提交图片文件与尺寸，并清除预览。依据为实时 React 组件源码只读检查，未调用私有回调。初期未选择文件；随后完成一次1像素合成PNG的非发送检查，确认原File引用与尺寸保留，再通过原站取消按钮清空，未点击发送。

文件入口接受 PNG／JPEG、支持多选；本工具首版每条仅一张、小于 2 MiB，整个消息组仍为 1–10 条。选图与发送分别控制；媒体解析期间不推进，所有最终发送仍使用正常发送按钮。

## 分工与接口

1. `core/image-assets.mjs`：独立 `creatorImageAssets`，最多20张、JSON上限4MiB，不自动淘汰；校验真实格式、尺寸、大小、SHA-256，按摘要去重。异步 read/list/add/get，同步 normalizeImageReference/imageReference。模板、队列、历史仅保留 `{type:'image',assetId,sha256,name,mime,size,width,height}`，不复制图片二进制。
2. `queue.mjs`、模板与历史：混排消息，图片命令包含 image 引用、text为空；逐条索引、暂停、人工核对与旧消息分支保持兼容。补混排、损坏引用、迟到回包、恢复测试。
3. `dashboard.*`：文件导入、已存图片选择、缩略预览、失败保留旧图、异步迟到保护；模板可复用图片。历史显示图片元数据，说明导出记录不等于图片原件备份。
4. 主线程集成 `backend.mjs/page-snapshot.mjs/content.js`：独立图片接口在业务初始化前分流；资产先落盘再引用。受控预备动作先保存令牌，再在MAIN核对原店铺／文档／达人／名单和空草稿后设置文件。解析出的原始File引用、唯一令牌和元数据一致才可授权；声明落盘后同步复核并点击正常发送按钮。演练不设置文件、不点击发送。

## 保护与证据

图片入口、成功回调与发送处理器使用已观察代码的长度与FNV指纹作为兼容开关（上传1241:b230b83e、成功回调134:4339807d、发送1544:f004a760），并核对onSuccess确实绑定当前组件的已核实方法，不复制原站脚本；变化时阻止图片动作，保留文字原链。文件变化只进入本地预览的结论必须持续匹配此版本。预备期间切换收件人或控件、已有草稿／附件／回复卡片、文件引用不一致均阻止最终点击；不擅自清空人工草稿或附件。

点击前MAIN同步标记图片令牌已消费；点击后不等待平台接受、上传成功、送达或已读，只等待本地待发送预览清空后继续组内下一条。相同图片的连续条目也必须按任务和条目索引分别识别，不能把上一条未清空的附件视为本条。点击或保存结果不明待人工核对，不重新选择图片或重试点击。重启后原内存文件引用失效，旧预备图不自动认领。

## 验证

先完成资产、队列、UI和后台窄测，再跑正式测试（排除用户暂停的local-build）及脚本检查。使用本地内存替身测试选图、图文混排、暂停恢复、声明前零点击、换达人零点击、重复请求、资产丢失和存储失败；真实页面仅允许非发送检查，若需发图验收须用户明确指定测试达人和图片内容。
