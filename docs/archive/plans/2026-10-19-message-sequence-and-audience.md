# 消息编排、达人来源与工作台改版

用户要求参考虾秘提高模板自定义程度，研究第二步发送模式，并使用 awesome-design-md 优化页面。已授权直接开发，保留工作区供审阅，不创建分支、提交或执行真实私信。

## 实现边界

- 消息由固定话术加链接扩为 1–10 条可排序文字／链接；文字支持姓名变量及 2400 字，链接以普通聊天文本提交。消息类型、顺序、任务名称进入预览签名；新配置不混用旧字段。
- 逐条沿用授权、持久化声明和 MAIN 同步核对。人工核对仅确认当前条，余下消息保持暂停，已提交前缀不重发。旧单／双消息任务和模板继续可读，不自动迁移正在运行的任务。
- 第二步称“达人来源”，与演练／真实发送区分。支持当前达人广场与指定 Shopee 用户 ID，指定名单不得补入其他人；支持姓名包含／排除，防重发、拒绝名单及聊天入口检查保持强制。来源／条件变更必须重新准备并锁定。
- 类目、社媒、粉丝、GMV 等先由用户在 Shopee 原页面筛选，再准备；排行榜、联盟伙伴管理及达人库缺少执行证据，暂不加入可执行来源。
- 图片输入已在真实聊天 DOM 确认支持 PNG/JPEG、多选；没有选择文件，选图是否立即发送、上传状态及最终提交条件均未验证，不接入真实发送或冒充可执行选项。
- awesome-design-md 选 Shopify 浅色事务后台，白／浅暖灰背景、清楚的卡片层级与两步表单，保留橙色主操作；无需外部字体或运行依赖。

## 并行分工

1. 消息核心：队列、模板、历史及对应测试。
2. 名单核心：来源校验、名单收集及对应测试。
3. 工作台：消息编辑、两步流程、模板套用、来源表单、响应式样式及 UI 测试。
4. 主线程：后台集成、接口约束、真实页面非发送检查、跨层测试与浏览器验收。

## 验证

优先测试 1／10 条边界、任意条暂停／迟到回包／人工核对、旧配置兼容、指定 ID 缺失／被拦截、来源与预览签名变化；再运行正式 Node 测试与语法／权限检查。用内存替身后台在浏览器验证编辑、排序、模板和来源交互，禁止真实发送。暂停中的本地测试插件不生成、不修复、不安装，相关既知生成器失败单列说明。
