# 独立任务历史实施计划

目标：保留多次任务的配置与逐人结果，提供独立的筛选、只读详情与 JSON 导出。

## 设计与边界

- `creatorTaskHistory` 独立保存已被替换的结束任务；当前任务直接从 `creatorQueue.task` 合并展示，按任务 ID 去重。旧数据缺少历史键时视为空，不改变现有队列版本。
- 新任务校验成功后，先确认旧结束任务归档成功，再保存新任务。归档失败只阻止本次新建，不覆盖旧任务、不锁死运行队列；逐条授权、提交及恢复不额外保存历史。
- 快照只保存配置与结果，不保存页面绑定、执行会话或授权。省略逐人重复的消息正文，以原模板、链接和达人姓名保留内容依据；旧单消息任务保持兼容。
- 历史最多归档 100 个任务、JSON UTF-8 总量 3 MiB；达到上限时保留全部原数据并阻止替换，不自动清理。当前任务另行合并，列表最多 101 条。
- `history.html` 使用独立脚本；只读历史接口在业务初始化之前校验来源并读取，不触发过期、重连、页面注入、发送或写盘。历史页没有队列操作权限，业务写盘故障时仍可读取、导出。

不新增任务删除、历史重发、定时任务、图片、多渠道或任意消息编排；现有防重发索引与“已提交”口径保持独立。消息模板与编排作为下一阶段。

## 文件与职责

1. `extension/core/task-history.mjs`：纯快照、校验、归档、筛选、摘要和导出；`tests/task-history.test.mjs` 覆盖兼容、容量、字面内容、特殊 ID 和日期边界。
2. `extension/core/backend.mjs`：启动边界归档及历史只读接口；独立 backend 行为测试覆盖存储故障、重启去重、来源校验及无业务副作用。
3. `extension/history.html`、`history.mjs`、`history.css`：筛选、10 条分页、详情、导出和空/错误状态；只为 `dashboard.html` 增加入口。UI 行为测试覆盖筛选、分页、详情、导出及响应竞态。

纯模块接口：`emptyTaskHistory`、`readTaskHistory`、`archiveTask`、`listTaskHistory`、`getTaskHistoryDetail`、`exportTaskHistory`。后台接口：`panel:history-list`、`panel:history-detail`、`panel:history-export`。
