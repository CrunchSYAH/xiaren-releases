# 需求4：移除工作台网页名称搜索

日期：2026-10-22（Asia/Shanghai）。按需求4独立对话中用户后续明确回复“删除”执行；图四红框为工作台的“Shopee 达人名称搜索”。

## 当前行为

- 工作台移除名称搜索控件、草稿字段及对应页面操作；新准备只传分类和社媒，不清空 Shopee 原页人工名称条件。本地“姓名包含／排除”仍保留，二者用途不同。
- MAIN 适配器公开的 `supported/current` 及请求仅含 `category/channel`；真实网页名称条件只读参与完整筛选锁，维持旧锁的序列化形状，并继续包含表单、实际应用条件与排序。人工名称尚未 Apply 时，不代替用户点击或修改其他筛选，提示先在原页处理。
- 旧 `source.webFilters.search` 按原规则校验并保留，兼容历史查询／导出／归档、已锁定名单和暂停任务。工作台对照可编辑条件后，预览／启动仍交付原名单来源，不改写原锁定配置。
- 新准备请求含旧搜索参数会明确拒绝；恢复的未完成网页搜索准备在任何筛选操作前标记失效，提示重新准备。不会自动恢复搜索动作或悄悄忽略其条件建立新名单。
- 保留分类／社媒胶囊、后台来源导航、默认复选项、当前位置、10%候选池及勾选、名单／队列分页等其他需求的现有行为。

## 根因与修复

原删除改动拒绝了旧存储里的搜索字段，并从筛选锁移除该字段：前者使正常旧历史误报“损坏或版本不兼容”，后者会破坏已锁定名单的精确核对。工作台新表单与旧来源比较也会不相等，阻止有效名单启动。

保留旧值的读取兼容和旧锁格式，同时在新准备与实际页面操作边界禁止搜索。没有迁移、清空或批量重写用户数据，后台及 MAIN 仍使用原来的精确名单核对。
