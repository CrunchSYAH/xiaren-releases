# 打开专用页后直接准备名单

## 操作变化

现在的流程为：打开专用 Shopee 页 → 登录并筛选达人 → 填写人数 → 准备名单。取消独立“读取当前页名单”按钮、前端读取事件及后台 `panel:refresh` 入口；“准备名单”本来就实时读取专用页面，继续复用这条核对链。

已连接原页面但店铺尚未识别、或已切换账号时，可以直接准备，不再被旧工作台连接结果阻断。准备成功会更新店铺、名单和准备状态；切换账号撤销发送确认，只有按新店铺成功准备后才能重新确认发送。

页面连接尚未完成时等待连接；未登录、验证限制或原文档变化时继续阻止准备并显示原因，不会复用旧店铺名单。真实发送、原文档绑定、名单锁定和消息基线逻辑未调整。

## 验证范围

新增前端回归先复现多余读取按钮及切换账号后的准备阻断，再验证直接准备、自动识别店铺、重做发送确认和页面未连接阻断。后台回归覆盖首次连接未登录后直接准备、准备时重新获取当前店铺及名单、未登录或受限阻断与同页恢复；文档、时间基准及存储检查继续执行。

正式功能109/109项测试通过、零失败；正式扩展8个脚本通过语法检查，网站与扩展权限未扩大，未新增外部请求：

```powershell
node --test tests/backend.test.mjs tests/content.test.mjs tests/dashboard.test.mjs tests/guards.test.mjs tests/queue.test.mjs tests/snapshot.test.mjs tests/collection.test.mjs tests/target-*.test.mjs
```

本轮不运行、生成、安装或修复已搁置的本地测试插件，也不运行依赖该测试版的全仓入口。验证使用正式源码的 Node 行为测试和语法、权限检查；没有向真实达人发送消息，没有重载用户当前正在使用的扩展。

## 使用更新

在 `chrome://extensions` 重新加载正式“虾仁”，再从工具栏打开工作台。更新后不再有“读取”按钮；专用页登录并连接后，直接点击“准备名单”。如旧任务尚未结束，仍需先按原任务流程核对并结束。
