# 首次聊天缺少历史基线的问题

> 历史方案：用户随后要求提交后继续、不等待回执。当前版本已移除此基线要求，见 `verification-2026-10-16-submit-and-continue.md`。

## 根因

用户在正式插件尝试真实发送时，后台提示“当前聊天缺少可靠的历史记录，无法核对发送结果；已阻止发送”。只读检查确认任务已暂停，100项均为待处理，未获得发送许可，输入框为空。

当前首次聊天的最新消息编号为空字符串，而原解析器只接受有效消息编号或页面明确提供的零。它无法区分“历史尚未加载”和“已确认没有历史”，因此在授权前保守阻止首次发送。

## 正式页面证据与修复

实站只读检查发现当前聊天为首次会话；消息组件的请求状态为 `succeed`，消息列表为空，前后均无更多记录，可读取标记为真。聊天编辑器、消息组件及按当前会话编号保存的消息记录指向同一店铺、收件人和会话。

只修改 `extension/page-snapshot.mjs` 的基线读取：

- 仍优先使用有效历史消息编号；空字符串本身不能作为零。
- 仅在首次会话标记、空的最新消息编号与时间、身份一致、请求成功、当前列表为空以及本会话缓存记录为空等证据同时成立时，建立零基线。
- 全局请求成功不能单独证明当前会话为空；必须存在以当前会话编号保存的实际空记录，且该记录前后均无更多消息，也无失败消息。读取状态异常时继续阻断。
- 最终点击前在原同步核对函数中重新计算证据；证据失效或身份变化则不点击。新消息出现时使用新的历史编号，原单次许可、名单锚点与回执核对流程继续生效。

没有调整网页、网站权限、发送按钮逻辑、队列或历史记录。真实账号的原暂停任务未恢复，未填草稿或点击发送；未重载用户正在使用的正式扩展。

## 验证

先用回归测试复现“成功空历史仍被阻止”，修复后通过；再复现“上一会话全局成功状态但当前无记录仍可点击”的缺口，加入当前会话记录校验后通过。

新增行为覆盖：成功空历史、证据缺失/未成功/仍有消息/身份变化、最终点击前证据失效、空历史后新回执、旧全局状态及状态读取失败。原数字基线、旧消息延迟加载、单次提交、名单边界等检查继续执行。

修改后的生产读取函数已在用户当前真实聊天页进行只读检查，识别到空历史证据、零基线和回执结构，输入框保持为空；这不是实际发送验收。

正式功能的以下检查为104/104通过、零失败；正式扩展8个脚本通过语法检查，权限未变化：

```powershell
node --test tests/backend.test.mjs tests/content.test.mjs tests/dashboard.test.mjs tests/guards.test.mjs tests/queue.test.mjs tests/snapshot.test.mjs tests/collection.test.mjs tests/target-*.test.mjs
```

没有运行 `scripts/check.mjs` 或全仓测试入口，因为它们会生成或验证已被用户搁置的本地测试版；本轮只检查正式扩展脚本及正式行为测试。

按用户指令，没有运行、生成、安装或继续修复本地测试插件。未向真实达人发送消息，真实发送与送达尚未验证。

## 如何使用修复

1. 在 `chrome://extensions` 为正式“虾仁”扩展点击“重新加载”，再从工具栏打开工作台；只刷新工作台不会更新后台。
2. 重载会使旧专用页绑定及锁定名单失效。先结束当前暂停任务，再打开新的专用 Shopee 页并重新准备名单；首次验证建议将目标设为1人。
3. 核对账号、收件人与消息后，由用户选择真实发送。出现待人工核对时检查聊天实际结果，不直接重复发送。
