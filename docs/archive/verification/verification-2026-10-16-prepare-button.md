# 正式插件“准备名单”问题验证

## 根因与修复

Chrome 工具栏打开的正式工作台已读取新版源码，但已加载的扩展后台仍是旧版。旧后台不支持 `panel:collect`，返回“不支持此工作台操作”；只刷新工作台不能更新后台。

- 已重载正式扩展，重载前后原队列数据摘要一致；原任务为已完成的演练任务，没有中断发送。
- 后台状态声明目标人数能力；工作台遇到缺少该能力的旧后台时禁用准备入口，并在名单区域提示到扩展管理页重新加载，避免继续发出不支持的请求。
- 旧版本问题排除后，实站页面隐藏时追加停在首批名单。准备需要追加时，后台先保存准备状态，再激活专用标签页；界面提示 Chrome 和专用页保持前台可见。已备齐不切页，激活失败使准备失效，存储失败不会继续激活。

`active:true` 不能保证被其他应用遮挡的 Chrome 页面实际可见，用户仍需让专用页保持前台。本次未改页面滚动算法、网站权限或发送流程。

## 正式扩展实站验证

用户将专用页放到前台后，通过正式工作台的“准备名单”按钮发起目标100人的收集：

- 页面从24行逐批追加到108行，准备计数依次达到24、36、48、60、72、84、96、100。
- 最终状态 `ready`，目标100、已准备100、差额0；名单稳定标识去重后仍为100。
- 当前后台明确支持目标人数功能；原任务仍为 `completed`、`dry-run`，未启动新任务；页面没有打开聊天。

没有填写真实草稿或发送消息，没有保存真实店铺、达人身份或消息到本验证记录。此结果只证明当前正式扩展的名单准备链可用，不证明真实发送或回执可用；空白聊天缺少可靠消息基线时仍会阻止发送。

验证结束已取消本次临时准备并关闭自建检查页，确认用户原有店铺页仍在；下次使用须从工具栏打开工作台并重新准备名单。
