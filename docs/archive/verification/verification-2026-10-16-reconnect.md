# 筛选后卡在等待专用页面

## 实站诊断

用户打开正式专用页并筛选后，“准备名单”被禁用。只读检查发现：标签页匹配后台记录，Chrome状态complete，店铺可识别，36行达人已加载；但后台pageId、documentId、documentEpoch均为空，error为空，隔离世界的旧执行器stopped为真。当前任务completed。

代码存在同文档加载的连接缺口：loading会清掉绑定，complete注入content时若旧执行器仍活跃，初始化守卫直接返回，不再hello；旧执行器随后因已清空的文档绑定导致轮询失败而停止，此后没有握手建立新连接。旧工作台又依赖定时轮询，后台标签页节流会延迟界面反映已恢复的连接状态。

## 修复

- 后台对绑定缺失的专用页重新注入前，先在隔离世界停止旧执行器，避免旧初始化守卫跳过hello。
- 工作台轮询发现已记录专用页complete但pageId为空时补连；5秒节流避免握手尚在队列时重复重启。注入失败持久化错误并停止轮询重试，用户点击打开或页面重新加载后可重试。仍在loading时不补注入，外域仍阻断。
- 执行器在发送消息前和收到回复后都检查自身停止标记，旧异步操作不能继续填草稿、授权或提交。
- 工作台变为可见时立即刷新后台状态，不依赖被节流的定时器。

导航仍使原名单失效、暂停旧任务；恢复连接不会恢复发送或重新派发旧提交。原文档身份、名单与单次提交检查未放宽。

## 当前页面恢复证据

确认任务已完成后，仅向原专用页注入更新后的执行器完成握手，并通过工作台原“打开专用页”操作刷新显示。最终工作台为“专用页面已连接”，准备按钮可用；36行筛选名单保留，无聊天打开，消息模板保留。任务与防重发记录前后完整状态摘要一致。

未重载用户扩展或导航用户店铺页面，没有填真实草稿、打开聊天、准备新任务或发送消息。永久的后台补连修复需要在扩展管理页重新加载源码；本次当前连接已恢复，无需为继续操作立即重载。
