# 提交后继续下一位，不等待回执

## 最新行为

按用户最新要求，真实发送取得单次许可、完成最终同步核对并点击发送后，由后台直接保存“已提交”结果，按原设定间隔处理下一位。不再等待或读取平台接受、送达、已读回执，不再读取聊天历史或要求消息编号基线；此前空历史适配方案已移除。

“已提交”表示发送按钮完成一次受控点击，不证明平台接受或送达。点击后的异步拒绝、延迟失败及网络异常不会再自动识别，需在专用页面查看；这是取消回执核对后的结果口径。

## 状态与异常

- 后台在点击前保存单次声明；MAIN在同一同步操作内核对账号、收件人、原文档、路由、锁定名单与目标入口、草稿及控件。通过后只点击一次。
- MAIN正常返回后，后台在同一串行消息处理中保存提交标记、队列结果、防重发历史与下一位的最早处理时间；content不再轮询消息或另报发送成功。
- 真实任务的成功只可由受控点击推进，旧页面自报sent/failed无法跳过提交。已保存的提交不被迟到的结果回调撤销；重复提交或后台休眠恢复不重复点击。
- 点击返回丢失时暂停并保留待核对；点击前存储失败不点击，点击后保存失败停止推进，不能清除声明或重试。身份变化、限制、暂停停止、导航和原名单失效仍沿原流程阻断。
- 保留原持久化版本、状态值及单次声明键名，避免迁移旧数据；界面将sent显示为“已提交”。既有防重发与待核对记录继续生效，不会因更新清除。
- 独立审查复现授权拒绝后自动清理草稿的竞态：旧快照返回途中切换聊天且复用输入框时，可能误删另一会话的同文本草稿。已删除自动清空逻辑；拒绝或中断时保留草稿，并在暂停/待核对指导中要求检查。正常提交后输入框由平台处理。
