# 在真实页面脱敏副本中测试 Chrome 插件

推荐使用“真实页面脱敏重放 + 仅本机测试版插件”。产品仍是 Chrome 插件；本地网页只提供测试环境。正式版只支持真实印尼站，测试版只支持本机，两者独立加载、独立存储。

## 启动和加载

1. 双击项目根目录的 `启动本地测试.cmd`，保留命令窗口。需要 Node.js 22 或更新版本；脚本先生成测试版，再启动本机服务。
2. 在 Chrome 打开 `http://127.0.0.1:4177/` 查看测试指引。
3. 打开 `chrome://extensions`，开启开发者模式，加载本项目的 `artifacts\extension-local-test`。名称应为“虾仁 · 仅本地测试版”。以前已加载该测试版时，点击卡片的“重新加载”，再重新打开工作台；不要选择正式目录 `extension`。
4. 点击测试版图标，再点击工作台的“打开本地模拟页”。它现在打开脱敏重放页；页面左下角有样本与模拟模式控制面板。待加载完成后回工作台读取名单，初始店铺为脱敏名 `sample_shop`。

插件只操作它自己打开的标签页。直接打开网页仅供查看，不会被接管。重新加载扩展后会废弃旧页面绑定；有未结束任务时先按界面核对并结束，不要清除存储来绕过去重。

## 第一轮：原样检查

仅选“样本达人 01—03”，模板填 `Halo {{name}}, ini pesan uji.`，间隔 `2` 秒，上限 `2`。另外九位只有列表样本，没有聊天样本；点击他们会提示未采集，不能用来验收发送。

- 保持默认“演练”，核对右侧实时内容后直接启动：预期两人“已演练”、一人“已跳过”，页面的“离线发送点击”为 0。名单每页 10 人，翻页保留选择，全选只作用于本页。
- 保持页面左下角“保留实采状态”，工作台切换“本地模拟发送”，勾选确认并启动：预期因缺少可靠回执依据而暂停，点击数仍为 0。采到的三个真实空聊天都缺少历史消息基线，不能把空值推断为零。
- 不勾确认，或修改模板后尚未重新确认，真实发送启动按钮应禁用；没有手动生成预览的步骤。

## 第二轮：明确开启模拟交互

每次更换场景前，先暂停并结束旧任务；有“待核对”项须先人工处理。页面左下角选所需模拟模式，再点“新模拟店铺批次”，回工作台重新读取名单、核对内容并确认。批次会人为改变脱敏店铺标识，以保留旧防重发记录并隔离新一轮测试。

- **模拟：提供成功回执**：选前三人、上限两人，预期成功两人、跳过一人，点击数为 2；重复该批次不应重发。成功回执由本地替身制造，不是实采证据。
- **模拟：仅回显，结果不明 / 明确失败**：前者等待约 10 秒或更久后进入待核对，不自动重发；后者暂停，恢复时跳过失败项。
- **派生异常与中断**：收件人变化、验证提示或控件缺失应阻止发送/暂停。运行期间暂停、刷新或关闭专用页面，队列不应自行重发；结果不明先核对。

后台页面计时可能被 Chrome 延后。更长的等待不是重发依据。不要在运行中修改控制面板或手动切换聊天，除非正在测试该中断场景。

## 样本来源与测试价值

2026 年 10 月 16 日在工具新建的真实页面中，只读采集了四份样本：12 位达人的列表、前三位达人的空白聊天。采集保留实际 DOM 层级、允许的计算样式及必要运行状态的原始层级和当前分支；没有在真实页填草稿或点击发送。

数据在浏览器内先脱敏再写入本地：账号、达人身份、文本、头像和资源地址替换或移除，原站脚本、事件和凭证不保存。样本清单及 SHA-256 摘要见 `tests/fixtures/recorded/manifest.json`，离线加载前核对摘要。

这比手写模拟页多验证了一层：同一个页面识别器可以读取真实采集的结构，并与采集时的观察逐字段对比。四份样本已对比一致；原样空基线会阻止点击，派生成功/失败/异常及完整执行器流程另行检查。

仍有明确边界：没有真实历史消息、成功/失败回执、网络发送过程或平台风控样本；原站应用并未完整复制，点击和状态变化由本地替身提供。计算样式重放也不等同于像素完全一致，远程字体、图片和原交互脚本均已移除。

自动浏览器检查以替身 Chrome API 连接实际后台和执行器源码，验证页面执行链；**只有加载测试版后亲自运行，才能验收真实 Chrome 的权限、注入、消息与存储环节**。二者均不能证明平台真实发送可用。

## 隔离与结束

测试版权限仅 `http://127.0.0.1/*`，执行代码进一步限制为 4177 端口，不具有真实店铺权限。重放页只加载本机样本，CSP 禁止外部网络、原站脚本及表单提交；正式扩展不增加本机权限。

结束后在启动窗口按 Ctrl+C 停止服务，关闭测试页即可。不要把离线结果当作真实达人已联系记录。

开发命令：`node scripts/build-local-test.mjs`、`node --test tests/*.test.mjs`、`node scripts/check.mjs`。启动预览服务和已连接 Chrome 的 CDP Proxy 后，可运行 `node scripts/verify-recorded-page.mjs` 检查重放结果，输出在 `artifacts/recorded-verification.json`。

启动入口使用 ASCII 与 Windows CRLF 换行；`启动本地测试.cmd --check` 只检查环境及生成测试版，不启动常驻服务。原手写页 `/tests/fixtures/marketplace.html` 与替身工作台 `/tests/fixtures/workbench.html` 继续用于开发回归，不是当前插件测试入口。
