# 两个 Chrome profile 运行两个店铺

适用前提：两个店铺分别登录两个不同的 Chrome 个人资料（profile），而非仅打开两个普通窗口。每个 profile 运行一份虾仁，各有自己的工作台、专用 Shopee 页与队列，无需改动后台或迁移旧数据。

## 部署与操作

1. 在店铺 A 所在的 Chrome profile 打开 `chrome://extensions`，开启开发者模式，加载 `D:\Documents\ChatGPT\虾秘\extension`；已加载则保留原实例，不卸载。
2. 在店铺 B 所在的 profile 重复加载同一文件夹；不必复制源码。分别从各自工具栏打开虾仁工作台和专用 Shopee 页。
3. 各工作台核对各自店铺，分别配置消息、准备名单和确认。控制 A 的启动、暂停或继续要在 A 的工作台操作，B 同理。
4. 首次检查先在两个工作台都主动切换为“演练”（当前默认是真实发送），再准备名单和启动；演练不填入草稿、不点击发送。
5. 更新共用源码前先暂停两边并核对当前结果；更新后在两个 profile 中分别重新加载扩展、重新打开工作台并检查连接。未结束任务不能在另一个店铺继续，重新连接不自动恢复发送。

两个 Chrome 窗口都应保持打开，避免关闭或手工改动运行中的专用页。后台页面可能被 Chrome 节流，双实例不保证同时点击或固定完成速度；准备名单需要显示原页时仍可能切换焦点。

## 数据边界

- 队列、任务记录、防重发／拒绝记录、达人库、模板和图片分别保存在各 profile，使用同一源码目录不会让这些数据共享。
- A 的提交记录不会自动阻止 B 再联系同一个达人；本方案不引入跨店铺防重发规则。
- 一个工作台只控制当前 profile，不能统一控制另一个 profile，也不能直接查看另一边的历史。
- 不要卸载扩展、清理扩展数据或把旧存储覆盖到另一个 profile；本次无需这些操作。

## 非发送验收

以下为待执行检查，不是实机通过报告。开始前确认两边均为演练；已有未结束真实任务时先暂停核对，不为验收强行结束或覆盖。

1. 两边分别打开工作台与专用页，核对显示店铺各自正确，并各准备少量名单。
2. 各自启动演练，核对名单、进度与任务记录对应当前店铺。
3. A 演练未结束时暂停，检查 B 不被暂停；若演练已完成，重新安排可观察的演练任务再检查，不以完成状态代替暂停验证。
4. A 无运行任务时关闭其专用页，检查 B 连接、名单和任务不受影响，再由 A 工作台重新打开自己的专用页。
5. 分别刷新工作台查看记录，确认各自数据仍在，记录每项实际结果；任何串店或异常先停止对应实例并导出排查日志。

真实发送和发图仍需另行指定测试达人及明确授权；演练成功不能证明平台接受、送达或已读。
